# 猛人学习命令行（给 AI Agent 调用）

让 Claude Code、Codex（以后是 ChatGPT Dots）不用点界面，直接调用猛人学习整理课程。

**做的事和在软件里点「一键整理」一样**，步骤顺序也一样：

| 步骤名 | 中文 | 什么时候跳过 |
|---|---|---|
| `transcribe` | 生成字幕 | 已经有字幕 |
| `correct` | AI 校对（按术语表） | 没有绑定老师 / 术语表；已经校对过 |
| `frames` | 找关键帧（挑必要的插图） | 音频文件；没设置能看图的 AI；已经挑过 |
| `recheck` | 用画面复核存疑句 | 同上；没有存疑句；已经复核过 |
| `translate` | 翻译 | **中文视频不翻译**；英文视频翻译后软件里中英同时显示 |
| `summary` | 课程重点 | 已经有课程重点；媒体库里这个文件夹设了「不写课程重点」 |
| `review` | 查漏补缺 | 设置里关掉了；已经查过；文件夹设了「不写课程重点」 |
| `terms` | 新术语 | 没有绑定老师；已经找过 |

以前（还没有步骤记录时）在软件里写过课程重点的课，找关键帧、复核存疑句、查漏、新术语都当作做过了。

「不写课程重点」是用户在软件媒体库里给文件夹设的（灵修类这种逐字稿课程，只识别、校对，直接蒸馏老师），下层文件夹沿用。这样的课不写课程重点也算整理完；真要写某一节：`--steps summary,review --force`。

书籍和文档：`chapters`（没认出章节时让 AI 读目录分章）→ `organize`（逐章整理，含查漏、回页面核对）→ `overview`（全书总览）。

**不做的**：剪藏到 Obsidian、勾选新术语、打开「已校对」。这些由你在软件里人工校对后自己做。整理结果写在视频旁边的字幕文件里，软件的媒体库里直接能看到（点媒体库上方的刷新按钮）。

---

## 怎么调用

在项目文件夹里：

```bat
D:\mengren-learning\mengren.cmd <命令> [参数] [--json]
```

所有命令加 `--json`，结果以 JSON 写到 stdout，进度写到 stderr。**stdout 一律是 UTF-8，读取时要按 UTF-8 解码**：中文 Windows 默认按 GBK 读，会把中文后面的反斜杠吞掉，JSON 解析失败。Python 里设 `PYTHONIOENCODING=utf-8` 或 `subprocess.run(..., encoding='utf-8')`。退出码：`0` 成功，`1` 失败（看 JSON 里的 `error_code`），`2` 参数写错，`3` 读不到数据。

## 命令

| 命令 | 作用 |
|---|---|
| `list [--course 课程] [--todo] [--since today] [--kind video\|book]` | 列出媒体库里的视频和书 |
| `find [关键词] [--course 课程] [--index 12] [--todo] [--since today]` | 查找视频 |
| `info <路径或 video_id>` | 一个视频的详细情况：时长、字幕状态、做过哪些步骤、还要做哪几步（`next_steps`，不用做的步骤和原因在 `skipped_steps`；`processed` 表示都做完了）、最近的任务。只读，不改任何东西 |
| `process <路径或 video_id …>` | 整理（一键整理，不剪藏） |
| `process --course 课程 [--index 12] [--todo] [--since today] [--limit N]` | 按条件选一批来整理，一节一节做 |
| `process … --dry-run` | 只看会整理哪些、**真正还要做哪几步**（做过的、不用做的不列，原因在 `skipped` 里），不执行 |
| `process … --steps a,b` / `--skip a,b` | 只做 / 跳过某几步 |
| `process … --steps a,b --force` | 这几步做过也重做（`--force` 必须和 `--steps` 一起用，免得把字幕也重新识别、重复花钱） |
| `process … --lang zh\|en --provider doubao\|openai\|siliconflow` | 指定语言、识别服务（默认按软件设置） |
| `process … --doubao-model auto\|stream2\|flash\|std1\|std2` | 这次豆包用哪种模型（`auto` 按顺序自动换；不写就按软件「设置 → 豆包语音」里选的）。选定一种时只用这一种，出错就停，不换到别的模型 |
| `process … --doubao-account auto\|名字\|第几个` | 这次用哪个豆包账号（`auto` 从账号 1 开始按顺序换；不写就按软件设置里选的）。选定时只用这个账号，出错就停，不换到别的账号 |
| `process … --model cloud\|local` | 识别方式。现在只有 `cloud`（云端）；`local`（本地模型）接口留着，还没接入 |
| `run <步骤> <路径或 video_id> [--force]` | 只做一步 |
| `steps` | 列出所有步骤 |
| `tasks [--limit 20]` | 最近的任务 |
| `task <task_id>` | 一个任务的完整记录 |
| `resume <task_id>` | 接着做没做完的任务（做完的步骤自动跳过） |
| `cancel <task_id>` | 让正在运行的任务停下 |

**选视频**：
- `--course`：媒体库左边的文件夹名，或它下面的子文件夹名，包含即可；
- `--index`：在这个课程里是第几个，从 1 开始，顺序和软件左边列表一样；
- `--todo`：**还没整理完的**：按一键整理默认的步骤（上面的表）还有没做完的。判断规则和真正整理时「已经做过、跳过」的规则是同一个，不该做的步骤不算（中文不翻译、音频不找插图、没有老师不校对不找新术语）。所以：写完课程重点后额度用完、查漏或新术语没做的课也会选上（以前只看有没有课程重点，会漏掉）；只有查漏、复核存疑句这种「失败了不影响后面」的步骤失败的，也算没整理完。书：还有章节没整理，或还没写全书总览。
  `list` 里这种课的状态是「未整理完」，后面写着「还差：查漏补缺、新术语」，JSON 里是 `pending_steps`；软件媒体库里同样标「未整理完」。再整理时只做还差的那几步。
- `--since today`：今天新增的（按文件下载时间）。

**video_id**：12 位编号，由文件完整路径算出来，同一个文件永远是同一个编号。文件改名或移动后编号会变。

## 例子

```bat
rem 某课程第 12 个视频，整理
mengren.cmd process --course 峰级分析 --index 12 --json

rem 今天新增、还没整理的全部整理
mengren.cmd process --todo --since today --json

rem 先看看会做什么
mengren.cmd process --course 市场观念 --todo --dry-run

rem 只重新生成课程重点（含查漏）；用户在软件里手动插进课程重点的截图会按出处时间放回去，裁剪、大小照旧
mengren.cmd process <video_id> --steps summary,review --force --json

rem 上次失败了，接着做
mengren.cmd resume 20261014-091520123-ab12 --json
```

失败时：`"success": false`，`stage` 是出错的那一步，`error_code` 见下表，`retryable` 表示过一会儿 `resume` 能不能好。

| error_code | 意思 | 自动重试 |
|---|---|---|
| `network` | 网络出错、连接失败、超时 | 每步自动重试 3 次（等 10 秒、1 分钟、3 分钟） |
| `overloaded` | 服务方太忙或内部临时出错：ChatGPT「servers are currently overloaded / try again later」、HTTP 502 / 503 / 504 / 529、豆包 55 开头的错误码（如 55000000 remote or network error） | 同上。豆包流式识别出这种错时先只重发出错的那一段 |
| `bad_output` | AI 返回的格式不对 | 同上 |
| `config` | 缺 API Key、没选模型、没登录、没装 ffmpeg | 不重试，先去软件设置里填 |
| `auth` | API Key 不对或没开通 | 不重试 |
| `quota` | 额度不足、欠费、请求太频繁、ChatGPT 5 小时用量限额（usage limit） | 不重试，马上停（就算说明里写了「稍后再试」） |
| `model` | 找不到所选的模型 | 不重试 |
| `media` | 视频读不出或损坏 | 不重试 |
| `not_found` / `not_in_library` | 文件不存在 / 不在媒体库里（Agent 只处理媒体库里的文件） | 不重试 |
| `busy` | 这节课正在被另一个任务整理 | 不重试 |
| `no_subtitles` | 没有字幕，后面的步骤做不了 | 不重试 |
| `not_supported` | 还不支持（例如本地模型） | 不重试 |
| `cancelled` / `interrupted` | 被取消 / 程序中途退出 | `resume` 接着做 |
| `internal` | 程序出错，详情在日志里 | 不重试 |

## 可靠性

- **任务记录**：每次整理一条，存在 `%APPDATA%\猛人学习\tasks\`，记下每一步的状态（pending / running / completed / failed / cancelled / skipped）、开始和结束时间、用的 AI 和模型、重试次数、错误。不写 API Key。最多留 300 条。
- **做到一半失败**：这一步什么都不写进字幕文件；前面完成的步骤已经保存。再运行同一节课（或 `resume`），会从失败的那一步接着做，前面的不重复做、不重复花钱。
- **校对前存历史版本**：AI 校对前，当前字幕会存进软件的「历史版本」，不满意可以在软件里恢复。
- **和软件同时用**：Agent 正在整理的课，在软件里打开会提示；Agent 改过的课，软件保存时不会直接覆盖，会先问你要哪一份。
- **日志**：`日志（可随时删除）\agent.log`。
- **从 Claude 桌面版里运行**：Windows 可能把写 `%APPDATA%` 的操作转存到 Claude 的私有文件夹。命令行发现后会自动改用 `\\localhost\C$\…` 读写你真正的数据；连这个也访问不到时，返回 `error_code: data`，请改在普通终端里运行。

## 和软件界面的关系

软件里的整理按钮和「一键整理」用的也是 `app/core/workflow.py`，和命令行完全是同一套规则，整理结果没有区别。区别只在默认选项：

- 命令行按「一键整理」默认打的勾来做，做过的步骤自动跳过；
- 在界面上点哪个按钮就做哪一步，做过的也重做。界面上还可以：没选老师也校对（会先问你）、中文也翻译、只整理勾选的章节、章节没全部整理完就先写全书总览。

## 以后接 MCP / Dots

业务都在 `app/core/workflow.py`，命令行 `app/cli.py` 和界面的 `bridge.do_steps` 都只是很薄的入口。以后加 MCP，就再写一个入口，调用同样的 `workflow.find / info / process / run_step / resume`，任务记录用 `core/tasks.py`。

MCP 用 stdio 方式，**不要开本机网络端口**：用户电脑上的 360 和 Clash 会干扰本机回环连接。
